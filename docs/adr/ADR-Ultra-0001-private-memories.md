# ADR-Ultra-0001：小秘密——单条记忆可设为来源角色私有

关联 Issue：[#1](https://github.com/Nomikfk1215/eidolon-sc/issues/1)。

当前所有角色共享同一用户的记忆。有些互动只希望留在用户和某位角色之间，因此增加「小秘密」：用户可以手动将一条记忆从共享切换为来源角色私有，再次点击恢复共享。此处记录采用的设计，功能尚待实现；[需求与验收](../../.scratch/small-secrets/spec.md)单独跟踪。

保留单份记忆存储，只新增共享／私有的可见范围标记。私有对象直接使用已有的 `source_character_id`，也就是记忆条中「对 xxx 说的」那位来源角色。首版每条私有记忆只属于一位来源角色，不增加角色选择器。

当前角色可读取的范围为「该用户的共享记忆 + 来源角色为自己的私有记忆」。先在后端过滤候选范围，再沿用现有相关性检索、重排和上下文拼接；私有化不要求每次注入全部私有记忆。已有记忆和普通新记忆默认共享。

记忆条的删除按钮左侧增加图钉按钮。未选中表示共享，选中表示私有，并在条目上显示「仅 xxx 知道」；按钮提示分别为「设为仅 xxx 知道」和「恢复为所有角色共享」。图钉只切换可见范围，不改变排序。状态保存到服务端，保存失败保留原状态并提示。

## Considered Options

- **单份记忆增加可见范围（采用）**：复用来源角色、现有记忆和向量，不复制数据，改动集中在可见范围过滤与读写规则。
- **每位角色各建一份记忆库**：共享记忆需要复制或同步，删除、更新和去重的复杂度都会增加。
- **只在最终提示词里要求保密**：其他角色的检索、重排或后台提炼仍可能接触私有内容，不能满足读取隔离。
- **允许任意选择多个角色**：需要额外的授权数据和交互，留到有明确需求时再做。

## Consequences

- 文字对话、通话、主动搭话、后台记忆提炼及检索失败后的备用路径，都遵守同一可见范围；在取得候选记忆时过滤，注入模型前校验，不能只在界面隐藏。
- 后台模型只看到当前角色可见的记忆。由私有记忆补充或取代而来的内容保留私有范围；若一条派生内容同时使用共享与私有信息，按私有保存，防止通过重新提炼扩散。新记忆的取代关系须由后端校验，不能取代当前角色不可见的记忆。
- 保留 ADR-0014 的「被取代的记忆仍可查看和删除」规则。切换可见范围不改变取代关系，也不自动恢复被取代的记忆。
- 私有化成功后，后续读取按新范围生效；已取得候选的进行中任务应在注入和写入前校验最新范围，相关缓存同步失效。已经发送给模型或出现在其他角色既有对话中的内容无法撤回。
- 用户仍能查看、删除自己的全部记忆。数据包保留私有标记，老数据包缺少该字段时按共享解释；新格式应升级版本，让不支持私有记忆的旧部署明确拒绝，避免静默丢失范围。导入去重不能放宽已有的私有范围，具体冲突处理在实现时确定。
- 来源角色已移除时，私有记忆保持私有，由用户决定恢复共享或删除。
- 首版逐条管理，不自动识别全部语义相似的记录。相同内容若另有共享条目，需要分别处理；用户向另一角色重新透露同一件事时，该角色仍可依据自己的对话获知。

## 与既有决策的关系

本决策在个人 fork 中替代 [ADR-0002](0002-shared-memory-with-source-character.md) 的「所有记忆无条件共享、不支持私密记忆」部分，采用该 ADR 已预留的可见范围扩展方向；单份存储、来源角色标注、不同用户隔离，以及共享记忆的转述口吻继续保留。

[ADR-0014](0014-superseded-memories-are-marked-not-rewritten.md) 的取代与删除规则继续适用，增加可见范围和派生内容的限制。[ADR-0025](0025-data-packages-leave-affinity-and-gifts-behind.md) 的数据包继续携带记忆，新增范围字段随记忆保存。
